## 一、买哪台机器（购买页逐项对照）

**进「学生用券专区」，筛选云服务器。下表左边就是购买页上的选项名，直接对着选：**

| 购买页选项 | 怎么选 | 说明 |
|---|---|---|
| 地域 | 华东1（杭州）可以；下拉里若有**华中1（武汉）/ 华南1（深圳）**就优先 | 离你越近延迟越低。中国内地流量单价都是 0.8 元/GB，选哪个都不影响价格 |
| 可用区 | **随机分配** | 单机部署，不涉及跨可用区容灾 |
| 实例规格 | **2CPU 2GiB**（`ecs.e-c1m1.large`，经济型 e） | 就是这档，一年 284 元、券全额抵扣。注意它是**共享型**，CPU 有性能基线（见下） |
| 镜像 | ⚠️ **必须改成 `Ubuntu 22.04 64位`** | 默认给的是 Alibaba Cloud Linux 3，用它会**让本手册全部失效**（见下） |
| 系统盘 | **ESSD Entry 40 GiB** | 够用。系统 + MySQL + uploads 约 15G，别选 20G |
| 公网 IP / 带宽 | ⚠️ **「带宽」一栏的值必须 > 0，填 `10` Mbps** | 填 0 等价于不分配公网 IP，买完只有内网地址（见下） |

> 想更稳可以加钱上 **2 核 4G**：券抵 300，自付差价。4G 不用做内存调优，最省心。

### ⚠️ 镜像必须换成 Ubuntu 22.04 LTS

购买页默认选中 `Alibaba Cloud Linux 3.2104 LTS`。它是 RHEL 系（用 `dnf`/`yum`），而本手册所有命令都是 Ubuntu 的 `apt`。用 Alinux 3 的话：

- MySQL 8.0 不在默认源里（默认只有 MariaDB），要手动加 MySQL 官方 repo 才能装 8.0
- 自带 Python 是 3.6（RHEL 8 系），低于本项目要求的 3.10；想升到 3.11 只能源码编译，没有 `deadsnakes` 这种现成源
- 出问题我也没法按本手册给你定位

**在下拉里找 `Ubuntu 22.04 64位`。** 找不到 22.04 就选 `Ubuntu 24.04`——能跑，但它是 Python 3.12 + MySQL 8.4（8.4 移除了 `mysql_native_password` 默认支持），和本手册有几处差异，告诉我我帮你改。

### ⚠️ 公网 IP 和带宽：这两项决定买完能不能访问

购买页这两行长这样（「带宽」一栏容易看漏）：

```
网络类型    专有网络
专有网络    默认专有网络          ← 保持默认
虚拟交换机  默认交换机            ← 保持默认
带宽        按使用流量  [ 10 ] Mbps   ← ★ 这里必须大于 0
```

**★ 带宽值必须改成大于 0，建议填 `10`。**

阿里云官方规则（帮助中心「IP地址」）：**默认不给实例分配公网 IP；把带宽峰值设为 0 Mbit/s 等价于不分配公网 IP；使用期间若把带宽值改成 0，已有的公网 IP 会被直接回收且无法找回。**

也就是说，购买页那个 `0` 如果原样提交，你会拿到一台**只有内网 IP** 的机器——SSH 进不去、网站打不开，等于白买。事后补救要么去控制台把峰值调到大于 0（包年包月实例支持），要么绑 EIP（约 ¥0.02/小时 ≈ ¥175/年，券不覆盖）。

**为什么建议 10 而不是拉满 200：**

按流量计费时，**费用只取决于实际用了多少 GB，跟峰值设多大无关**（阿里云文档原话：仅更改流量带宽峰值时不涉及费用）。峰值只是出网速度上限。所以：

| 峰值 | 首屏加载（约 500KB） | 万一被爬虫/扫描刷满一小时的流量损失 |
|---|---|---|
| 1 Mbps | 4 秒以上，很卡 | 0.45 GB ≈ ¥0.36 |
| **10 Mbps** | **约 0.4 秒，很顺** | **4.5 GB ≈ ¥3.6** |
| 100 Mbps | 约 0.04 秒 | 45 GB ≈ ¥36 |

峰值本身不花钱，但它决定了**被刷时每秒最多能烧掉多少流量**。你的场景是校园内演示 + 几个同学访问，10 Mbps 完全够用且风险可控，没必要为了那 0.36 秒的差别把上限开满。**这道题的正确解法是「够用 + 损失可控」，而不是「拉满」。**

> 第二道防线：开通 CDT 后可以在控制台设**流量限额**，用超自动停止计费，彻底避免被刷。

**改完带宽值后，回头看一眼右下角「应付费用」是否仍是 ¥0.00。** 如果变成了非 0，说明带宽有预付费用，先别付款，告诉我。

### ⚠️ 账户里留点余额

按使用流量是**后付费**（按小时结算出账）。账户余额为 0 时，阿里云会**暂停公网带宽服务**——表现为网站突然打不开，但服务器本身还在跑，很容易误判成程序崩了。

建议账户里留 **20~50 元**。有 CDT 的 20GB/月免费额度兜底，正常情况下不会产生费用，留余额只是为了不被判定欠费。

### 💰 顺手省一笔：开通 CDT 拿免费流量

按流量计费可以升级成**云数据传输 CDT**，开通后每月赠送公网流量：

| 地域 | 免费额度 |
|---|---|
| **中国内地（杭州等）** | **20 GB/月** |
| 非中国内地 | 200 GB/月 |

网上标题爱写「免费 200GB」，那是**境外**额度，杭州属于中国内地，实际是 **20GB/月**。按 0.8 元/GB 算，每月省 16 元、**一年 192 元**。

你这项目的出网流量估算：前端打包首屏约 500KB，一次完整访问（含接口响应）按 1MB 出流量算 → 20GB ≈ **2 万次访问/月**。面试演示加自己测试根本用不完，基本等于零流量成本。

> 开通入口：控制台搜「云数据传输 CDT」，开通后在 ECS 带宽计费里切到 CDT 模式。
> 另外记住：**只收公网出方向流量**——你上传简历 PDF、商品图（入方向）是免费的。

### 经济型 e 实例的性能基线

`ecs.e-c1m1.large` 是**共享型**实例，CPU 有性能基线（大约 10~15%），超出部分靠积分突发。影响：

- 跑 FastAPI + MySQL：**完全够**，日常负载很低
- `npm run build` 构建前端：**会明显慢**（可能 3~5 分钟），这是 CPU 密集操作

所以第二节必须加 swap。构建实在慢的话，改成**本机构建后上传**：`scp -r frontend/dist campus@<IP>:/var/www/campus/`，跳过服务器构建。

### 2 核 2G 的内存账

| 组件 | 常驻内存 |
|---|---|
| Ubuntu 22.04 | ~250 MB |
| MySQL 8.0（按第二节调优后） | ~400 MB |
| uvicorn + LangChain + SQLAlchemy | ~300 MB |
| Nginx | ~20 MB |
| **合计** | **~1.0 GB** |

能跑，但余量不多 → **必须加 swap**（见 2.3），否则 `npm run build` 和 `pip install` 装 LangChain 时有概率被 OOM Killer 杀掉，表现为莫名其妙的 `Killed`。

## 二、初始化服务器（一次性，约 15 分钟）

### 2.1 登录并放行端口

```bash
ssh root@<你的公网IP>
```

阿里云控制台 → 轻量应用服务器/ECS → **防火墙/安全组**，放行：

| 端口 | 用途 |
|---|---|
| 22 | SSH |
| 80 | HTTP（网站入口） |
| 443 | HTTPS（以后加证书用） |

**不要把 8001 放行。** 后端只监听 127.0.0.1，公网入口统一走 Nginx。

### 2.2 配国内镜像源（**国内服务器必做，不是"可选"**）

这三条能避开后面一整类"下载超时"的失败，省下的时间以小时计。

**① apt（系统包）** —— 阿里云镜像通常已指向内部源；若没有就换：

```bash
sed -i 's|//.*archive.ubuntu.com|//mirrors.aliyun.com|g; s|//.*security.ubuntu.com|//mirrors.aliyun.com|g' /etc/apt/sources.list
apt update
```

**② pip（Python 包）** —— **这条最关键，不配 `deploy.sh` 第 1 步大概率失败**：

```bash
cat > /etc/pip.conf <<'EOF'
[global]
index-url = https://mirrors.aliyun.com/pypi/simple/
timeout = 120
retries = 5
EOF
```

不配的话实测会撞上：

```
pip._vendor.urllib3.exceptions.ReadTimeoutError:
  HTTPSConnectionPool(host='files.pythonhosted.org', port=443): Read timed out
```

PyPI 默认的文件源 `files.pythonhosted.org` 在国内经常慢到读超时（pip 默认单次读超时只有 15 秒）。换阿里云镜像是内网直连，速度差一个数量级，**而且走内网不计公网流量费**。

> 写 `/etc/pip.conf` 而不是 `~/.pip/pip.conf`：前者对所有用户生效。`deploy.sh` 是以 `campus` 身份跑 pip 的，配在某个用户的 home 下容易漏。

**③ npm（前端依赖）**：

```bash
runuser -u campus -- env HOME=/home/campus npm config set registry https://registry.npmmirror.com
```

> 必须用 `env HOME=/home/campus` 指定 home，否则 npm 会把 `.npmrc` 写进 root 的 home，而 `deploy.sh` 是以 `campus` 身份执行 npm 的，读不到那份配置。

> 常用镜像备选：pip 用 `mirrors.aliyun.com/pypi/simple/` 或 `pypi.tuna.tsinghua.edu.cn/simple`；npm 用 `registry.npmmirror.com`（旧的 `registry.npm.taobao.org` 已停用）。

### 2.3 加 2G swap（**2G 内存的机器这步必做**）

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h          # 确认 Swap 一行有 2.0Gi
```

### 2.4 装系统依赖

```bash
apt update
apt install -y git curl build-essential nginx mysql-server python3-venv

# Node 20（Vite 6 要求 Node 18.18+，Ubuntu 22.04 自带的 Node 太旧）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs

python3 -V && node -v && nginx -v
```

**关于 Python 版本：不需要额外装 Python。** Ubuntu 22.04 自带 3.10，够用——`deploy.sh` 会按 `python3.11 → 3.12 → 3.10` 的顺序自动探测，取第一个 ≥3.10 的。

我扫过 `app/` 全目录确认过：项目没有使用任何 3.11 专属特性（`datetime.UTC`、`TaskGroup`、`tomllib`、`except*`、`typing.Self` 一个都没有），所以 3.10 跑得起来。

刻意**不**装 3.11 的原因：它必须走 launchpad 上的 `deadsnakes` 第三方源，国内网络未必拉得动，装不上就卡在半路。少一个失败点。

> ⚠️ `python3-venv` 这个包别漏。Ubuntu 把 `venv` 模块从 Python 本体里拆出来了，不装的话 `python3 -m venv` 会报 `ensurepip is not available`。

> **装到一半会弹出一个灰蓝色框**：`Which services should be restarted?`，里面列着 `networkd-dispatcher.service`、`tuned.service`、`unattended-upgrades.service`，底下是 `<Ok>` / `<Cancel>`。
> 这是 Ubuntu 预装的 `needrestart` 在问：它检测到系统库被升级了，依赖这些库的服务要不要重启。
> **直接按回车**（`Ok` 是默认选中项），这三个服务重启不影响你的会话。后面可能再弹两三次，统一按回车。
> **千万不要按 Ctrl+C** —— 那会中断 dpkg，把 apt 弄成半损坏状态，之后得跑 `dpkg --configure -a` 才救得回来。
> 想彻底免打扰，在跑 apt 之前先执行 `export NEEDRESTART_MODE=a`。

### 2.5 MySQL 建库建用户 + 内存调优

```bash
mysql
```

```sql
CREATE DATABASE IF NOT EXISTS campus_platform
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'campus'@'127.0.0.1' IDENTIFIED BY '换成你的强密码';

GRANT ALL PRIVILEGES ON campus_platform.* TO 'campus'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

> 密码**只能用 ASCII**，不能含中文。含中文会在驱动握手时抛一句毫无线索的 latin-1 编码错误（`app/config.py:63` 已经把这种情形拦成可读提示了）。

**2G 内存必做的调优** —— 编辑 `/etc/mysql/mysql.conf.d/mysqld.cnf`，在 `[mysqld]` 段下追加：

```ini
innodb_buffer_pool_size = 128M
performance_schema = off
max_connections = 50
```

```bash
systemctl restart mysql
```

> MySQL 8 的默认认证插件是 `caching_sha2_password`，它需要 RSA 加密来完成握手。
> `asyncmy` 在非 SSL 连接下会因此报 `RuntimeError: 'cryptography' package is required`。
> 本项目已在 `requirements.txt` 里补上 `cryptography`，不用你手动装。
> 万一还是报这个错，可以把用户改成旧插件：`ALTER USER 'campus'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '密码';`

### 2.6 建运行用户 + 拉代码

```bash
useradd -m -s /bin/bash campus
mkdir -p /opt/campus
chown campus:campus /opt/campus
```

#### 首选：从 codeload 下 tarball（实测唯一可行的方法）

**不要用 `git clone`。** 阿里云杭州 ECS 实测结果：

| 方式 | 结果 |
|---|---|
| `git clone https://github.com/...` | `curl 16 Error in the HTTP2 framing layer` |
| 加上 `git config --global http.version HTTP/1.1` 后 | `Failed to connect to github.com port 443`（12ms 即被拒 / 或超时） |
| **`https://codeload.github.com/...`** | **HTTP 200，179 KB，秒下** ✅ |

**被阻断的只有 `github.com` 这一个域名**，而 GitHub 用来提供文件下载的 `codeload.github.com` 是通的。所以直接下 tarball 比 `git clone` 更可靠。

```bash
cd /tmp
curl -fSL --max-time 90 -o campus-src.tar.gz \
  https://codeload.github.com/yijieshusheng666/campus-service/tar.gz/refs/heads/master
ls -lh campus-src.tar.gz          # 应约 180K

rm -rf /opt/campus && mkdir -p /opt/campus
tar -xzf campus-src.tar.gz -C /opt/campus --strip-components=1
chown -R campus:campus /opt/campus
ls -A /opt/campus                 # 应看到 backend  frontend  deploy  docs  README.md
```

> ⚠️ `--strip-components=1` 不能少。GitHub 自动打的包会多包一层 `campus-service-master/` 目录，要去掉。**注意这和下面本机 `git archive` 打的包不一样**，后者的顶层就是仓库根。

#### 以后更新代码

```bash
cd /tmp
curl -fSL --max-time 90 -o campus-src.tar.gz \
  https://codeload.github.com/yijieshusheng666/campus-service/tar.gz/refs/heads/master
tar -xzf campus-src.tar.gz -C /opt/campus --strip-components=1
chown -R campus:campus /opt/campus
cd /opt/campus && bash deploy/deploy.sh
```

> ⚠️ **更新时不要加 `rm -rf /opt/campus`。** 那个包不含 `.env`（被 gitignore）也不含 `.venv`（不在版本库里），
> 直接 `tar` 覆盖只会替换代码文件，而你辛苦配好的 `.env`、装好的虚拟环境都会原样保留。
> 一旦 `rm -rf` 掉，`.env` 就没了，`deploy.sh` 会以「`.env` 不存在」直接退出。
> （只有**首次安装**那一步才需要 `rm -rf`，因为要清掉之前失败 clone 的残留。）

> 这个包不含 `.git`，所以不能 `git pull`，每次都是整包覆盖（对部署来说没差别）。
> 想恢复 git 工作流，可把仓库导入 **Gitee**（支持"从 GitHub 导入仓库"），再改从 Gitee `git clone` —— 国内速度很快，`git pull` 也顺畅。

#### 如果 codeload 也不通：本机打包 + scp 上传

**① 本机打包**（仓库根目录；`git archive` 只导出纳入版本控制的文件，`node_modules` / `.venv` / `__pycache__` 自动排除）：

```bash
git archive --format=tar.gz -o ~/campus-src.tar.gz HEAD
```

产物约 180 KB，不必手工写 `--exclude`。

**② 本机上传**（Windows PowerShell，`scp` 是系统自带的）：

```powershell
scp "$env:USERPROFILE\campus-src.tar.gz" root@<你的公网IP>:/tmp/
```

**③ 服务器解包**：

```bash
cd /tmp && rm -rf /opt/campus && mkdir -p /opt/campus
tar -xzf campus-src.tar.gz -C /opt/campus
chown -R campus:campus /opt/campus
```

> ⚠️ 这里的 `--strip-components=1` **不要加** —— `git archive` 的包顶层就是仓库根，加了反而会把 `backend/` 削掉。这是它和 GitHub 自动打包唯一的区别。

> ⚠️ **scp 很可能报 `Permission denied (publickey)`，而且全程不弹密码输入。** 这不是密码错，是 Ubuntu 默认 `PermitRootLogin prohibit-password`：root 只接受密钥、不接受密码。（Workbench 的"免密连接"走阿里云自己的通道，不能代表标准 SSH 允许密码登录。）
> 需要开密码登录的话：
> ```bash
> # 必须在 sshd_config.d/ 下建 00- 前缀的文件，直接改 sshd_config 可能被覆盖（见踩坑表）
> cat > /etc/ssh/sshd_config.d/00-password-auth.conf <<'EOF'
> PasswordAuthentication yes
> PermitRootLogin yes
> EOF
> systemctl reload ssh
> ```
> 更安全的长远做法是用 SSH 密钥：本机 `ssh-keygen -t ed25519`，把公钥**文本**贴进服务器 `~/.ssh/authorized_keys` 即可（纯粘贴，不需要文件传输）。

> 本仓库为 **public**，无需 SSH key 或 Personal Access Token。

### 2.7 装 Nginx 与 systemd 配置

```bash
# Nginx：删掉默认站点，否则它抢占 80 端口，你打开看到的是 Nginx 欢迎页
rm -f /etc/nginx/sites-enabled/default

cp /opt/campus/deploy/nginx-campus.conf /etc/nginx/conf.d/campus.conf
nginx -t && systemctl reload nginx

# systemd 服务
cp /opt/campus/deploy/campus-api.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable campus-api
```

## 三、填配置并部署

```bash
# 1) 生成生产配置
cp /opt/campus/deploy/env.prod.template /opt/campus/backend/.env

# 2) 生成 JWT 密钥
python3 -c "import secrets;print(secrets.token_urlsafe(48))"
```

编辑 `/opt/campus/backend/.env`，填 3 处：

```ini
DB_PASSWORD=第 2.5 步设的密码
LLM_API_KEY=你的智谱Key
SECRET_KEY=上一条命令打印出来的字符串
CORS_ORIGINS=http://你的公网IP
```

```bash
chown campus:campus /opt/campus/backend/.env
chmod 600 /opt/campus/backend/.env      # 明文密钥，别让其他用户读
```

执行部署：

```bash
cd /opt/campus
bash deploy/deploy.sh
```

脚本会依次做完：装依赖 → 数据库迁移 → 构建前端 → 发布静态文件 → 重启后端 → 健康检查 → 重载 Nginx。任何一步失败都会停下并打印原因。

## 四、上线后验证清单

按顺序过一遍，每步都在验一个具体的链路：

| # | 验证动作 | 通过标准 | 在验证什么 |

| 4 | 注册一个账号并登录 | 能进首页 | **MySQL 连通**（第 2.5 步的关键验证） |

## 六、踩坑对照表

| 现象 | 真正原因 | 处理 |
|---|---|---|
| 结算页看不到这张券 | 没从**学生用券专区**进 | 回 `university.aliyun.com` 重新下单 |
| 买完只有内网 IP，SSH 和网站都进不去 | 购买页「带宽」值留成了 **0 Mbps**（不等于不分配公网 IP） | 控制台把流量带宽峰值改成大于 0；或绑 EIP（另收费） |
| 网站本来正常，某天突然打不开但进程还活着 | 账户余额为 0，公网带宽被暂停 | 账户留 20~50 元余额，并设 CDT 流量限额 |
| 首页加载慢到 4 秒以上 | 带宽峰值设太低（如 1 Mbps） | 调到 10 Mbps（按流量计费下峰值不影响费用） |
| 每月莫名产生流量费 | 没开通 CDT，白白错过 20GB/月 免费额度 | 控制台开通「云数据传输 CDT」 |
| 部署命令全部 `command not found` | 镜像选成了 Alibaba Cloud Linux 3（RHEL 系） | 重装系统为 Ubuntu 22.04，或用 `dnf` 重写所有命令 |
| apt 装到一半停住，弹出 `Which services should be restarted?` 灰框 | Ubuntu 预装的 `needrestart` 在问要不要重启被升级的库所依赖的服务 | 直接按回车选 `Ok`；想免打扰先 `export NEEDRESTART_MODE=a` |
| `python3 -m venv` 报 `ensurepip is not available` | 漏装 `python3-venv` 包 | `apt install -y python3-venv` |
| `pip install` 报 `ReadTimeoutError ... files.pythonhosted.org: Read timed out` | pip 默认源在国内慢到超时（默认单次读超时仅 15 秒） | 写 `/etc/pip.conf` 换阿里云 PyPI 镜像，见 2.2；脚本已加 `--timeout 120 --retries 5` |
| `npm install` 卡住或超时 | npm 官方 registry 在国内慢 | `npm config set registry https://registry.npmmirror.com`（注意指定 `HOME=/home/campus`），见 2.2 |
| `git clone` 报 `HTTP2 framing layer`，或 `github.com port 443` 连接被拒/超时 | 服务器到 **`github.com`** 这个域名不通（但 `codeload.github.com` 是通的） | 别用 `git clone`，直接从 codeload 下 tarball，见 2.6 |
| `scp` 报 `Permission denied (publickey)`，且全程不弹密码输入 | Ubuntu 默认 `PermitRootLogin prohibit-password`，root 只收密钥不收密码 | 见 2.6 开密码登录；更安全的是改用 SSH 密钥 |
| 改了 `/etc/ssh/sshd_config` 但 `sshd -T` 显示没生效 | Ubuntu 22.04 顶部有 `Include sshd_config.d/*.conf`，且 sshd 对同一项**取第一个出现的值** | 改在 `/etc/ssh/sshd_config.d/` 下新建 `00-` 前缀文件 |
| 解包后 `deploy/` 不见了 或 少一层目录 | `--strip-components=1` 用错：**GitHub 自动打的包要加，本机 `git archive` 的包不能加** | 按 2.6 对应方案处理 |
| clone 失败后重试提示目标目录非空 | 上次失败留下了残留的 `.git` | `rm -rf /opt/campus && mkdir -p /opt/campus && chown campus:campus /opt/campus` |
| `pip install` 中途 `Killed` | 2G 内存 OOM | 做 2.3 的 swap |
| 后端起不来，日志有 `'cryptography' package is required` | `requirements.txt` 缺 cryptography | 已补上；或改 `mysql_native_password` |
| 日志有 `latin-1 codec can't encode` | `.env` 的 `DB_PASSWORD` 含中文 | 改成纯 ASCII |
| 打开是 Nginx 欢迎页 | 默认站点没删 | `rm -f /etc/nginx/sites-enabled/default` |
| 刷新 `/goods/12` 变 404 | history 路由缺 fallback | 检查 `try_files ... /index.html` |
| 图片/简历 404 | `/static/` 没反代 或 uploads 权限不对 | 查 `location /static/` 与 `chown -R campus` |
| 私信收不到、控制台 `WebSocket connection failed` | Nginx 没转发 `Upgrade` 头 | 检查 `location /ws` 那两行 |
| 面试回答等很久后整段蹦出 | Nginx 缓冲了 SSE | 检查 `proxy_buffering off` |
| 上传图片报 413 | 请求体超 Nginx 上限 | 已设 `client_max_body_size 20m` |
| AI 功能返回兜底话术 | `LLM_API_KEY` 为空 | 填 Key 后 `systemctl restart campus-api` |
| 长回答中途 504 | 代理读超时小于 LLM 耗时 | 已设 `proxy_read_timeout 300s` |
| 域名访问不通 | **国内服务器未备案** | 先用 `IP:80` 访问；要绑域名必须先 ICP 备案（阿里云约 20 天） |

> **关于备案**：只用 `http://公网IP` 访问**不需要**备案。一旦想把域名解析到这台国内服务器，就必须先完成 ICP 备案，这一步没有绕过办法。面试演示阶段建议直接用 IP。
